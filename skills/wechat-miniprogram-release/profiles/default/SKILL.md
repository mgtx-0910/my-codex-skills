# marketingV2 小程序项目子技能

本文件是上级主技能显式读取的可替换项目规则；不负责选择通用上传渠道。向主技能交付：端、环境、两次构建选择、实际打包分支及 SHA、目标 AppID、产物绝对路径和验证结果。

## 项目和环境

- 仓库内 `code_V2.0/uni-cli` 是 C 端，`code_V2.0/uni-cli-emp` 是员工端。用户未明确指定端时默认 C 端；指定员工端时使用员工端。分别核实路径、脚本、依赖、平台选项和目标 AppID，不要混用配置或产物。
- 项目构建有两次选择：平台和接口环境。在所选分支的 `script/PLATFORMS/PLATFORMS.js` 中核实当前选项。无法通过用户指定或下列默认映射唯一确定平台及接口环境时，列出与其需求相关的实际平台和接口环境选项（分别编号，接口可附当前地址），一次询问用户选择；不要只笼统要求提供配置。用户明确选择后，若分支上的选项或地址不同，按实际配置重新核实并说明差异。不能确定时不得沿用 `.env` 旧值或自行猜测。

- 昌吉开发接口可能使用过期的穿透域名。以所选分支当前配置为准，调用实际业务接口检查连通性和返回值；失效时停止并提醒用户更换域名，且在微信小程序后台加入 request 合法域名。接口返回错误时结合请求参数排查，不凭普通 GET 状态码判定域名失效。

## 构建前同步主工作树和构建工作树

1. 每次构建前 `git fetch` 一次目标分支，记录拉取时的提交 SHA。未要求合并其他分支时，独立构建工作树从该 SHA 创建或安全更新；如果按用户要求合并，构建使用经核实的合并结果。
2. 用 `git worktree list --porcelain` 找到仓库的主工作树。若主工作树也检出同一目标分支、工作区和暂存区均干净，且当前提交可以快进到拉取的 SHA，则在主工作树执行 `git merge --ff-only <本次拉取的 SHA>`，并确认它已同步到该 SHA；已一致则无需更新。
3. 主工作树检出其他分支、存在未提交改动、领先或分叉而无法快进时，不切分支、不暂存、不重置或强行覆盖，说明未同步的原因，独立构建照常进行。构建期间远端有新提交，不再次拉取或重打包，除非用户明确要求重新打包。

## 构建

1. 在独立工作区或安全的现有工作区构建，保留用户未提交的代码。可复用经过核实的依赖，历史环境使用 Node 12.16.2；构建前检查 `package.json` 和本机实际版本。使用 `node_modules` 目录联接时确认实际输入和输出均来自预期工作区，避免覆盖别处产物。
2. 按两次选择写入工作区 `.env`，调用 `require('./script/manifest').statManifest()`，明确检查返回 `true`。该步骤读取远端平台配置并修改工作区文件，校验 AppID、平台和接口地址与目标一致。C 端昌吉开发曾使用 `wxfac067fa61fdd8b7`；员工端不能沿用，每次以远端配置与微信目标项目交叉核实，不只依赖历史值。
3. C 端和员工端的微信生产构建沿用各自项目的 `dist/build/mp-weixin`。在实际打包工作树的项目目录执行 `npm run builds`（微信构建并加固）。若 `node_modules` 通过目录联接指向其他工作树，构建前将 `UNI_OUTPUT_DIR` 显式设为**实际打包工作树中所选项目**的 `dist/build/mp-weixin` 绝对路径，以免 uni-app 按依赖所在位置解析输出。构建前核对输入目录、输出目录及实际工作树，使用现有 `dist/` 忽略规则。
4. 检查退出状态、编译及加固结果，确认产物确实由本次构建生成并位于上述目录，核验主要产物与实际接口域名，记录提交 SHA 和产物目录。上传时使用这次核验过的同一目录。不要把编译警告当作成功或失败的唯一依据。
