# marketingV2 小程序项目子技能

本文件是上级主技能显式读取的可替换项目规则；不负责选择通用上传渠道。向主技能交付：端、环境、两次构建选择、实际打包分支及 SHA、目标 AppID、产物绝对路径和验证结果。

## 项目和环境

- 仓库内 `code_V2.0/uni-cli` 是 C 端，`code_V2.0/uni-cli-emp` 是员工端。用户未明确指定端时默认 C 端；指定员工端时使用员工端。分别核实路径、脚本、依赖、平台选项和目标 AppID，不要混用配置或产物。
- 项目构建有两次选择：平台和接口环境。在 `script/PLATFORMS/PLATFORMS.js` 中核实当前选项。用户没有明确指定第二次选择且不能根据其明确表述确定时，先询问；不得沿用 `.env` 的旧值或自行猜测。
- C 端已知对应关系：昌吉开发为 `吉邮惠(昌吉开发)` → `昌吉开发`；昌吉正式为 `吉邮惠(昌吉正式)` → `昌吉正式`。用户明确说相应环境时可采用；另行指定第二次选择时以用户指定为准。员工端选项可能不同，查看其自身配置；目标环境不在选项中时向用户确认。
- 昌吉默认打包分支为 `feature_xcx2.5_1006080`；其他环境先核实默认分支，无法确定时询问。用户明确要求从某个分支直接打包时使用该分支，不自动合并到默认分支；给出分支但未明确要求直接打包时，将其合并到目标环境的默认打包分支，处理冲突并核实结果，再从合并结果打包。未提供分支时不额外合并，使用最新远端默认分支。用户另有明确合并目标或流程时遵从要求。构建前 fetch，记录实际打包分支和提交 SHA，保护其他改动。
- 昌吉开发接口可能使用过期的穿透域名。以所选分支当前配置为准，调用实际业务接口检查连通性和返回值；失效时停止并提醒用户更换域名，且在微信小程序后台加入 request 合法域名。接口返回错误时结合请求参数排查，不凭普通 GET 状态码判定域名失效。

## 构建

1. 在独立工作区或安全的现有工作区构建，保留用户未提交的代码。可复用经过核实的依赖，历史环境使用 Node 12.16.2；构建前检查 `package.json` 和本机实际版本。使用 `node_modules` 目录联接时确认实际输入和输出均来自预期工作区，避免覆盖别处产物。
2. 按两次选择写入工作区 `.env`，调用 `require('./script/manifest').statManifest()`，明确检查返回 `true`。该步骤读取远端平台配置并修改工作区文件，校验 AppID、平台和接口地址与目标一致。C 端昌吉开发曾使用 `wxfac067fa61fdd8b7`；员工端不能沿用，每次以远端配置与微信目标项目交叉核实，不只依赖历史值。
3. 按项目流程执行 `npm run builds`（微信构建并加固），确认输出位置。若共享依赖导致路径不明确，检查所用 uni-app 插件行为并显式设置 `UNI_OUTPUT_DIR` 为独立绝对路径。检查退出状态、编译及加固结果、主要产物与实际接口域名，记录提交 SHA 和产物目录；不要把编译警告当作成功或失败的唯一依据。
