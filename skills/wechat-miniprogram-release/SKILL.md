# 微信小程序发布

主技能负责通用流程；本技能当前配置的项目子技能是 [项目发布规则](profiles/default/SKILL.md)。执行前必须读取该子技能，按其中约定确认项目、环境、分支并构建。不要把其他项目的配置或产物代入。用户要用于其他项目或替换个性逻辑时，替换该子技能路径并先读取新子技能；新子技能应提供项目选择、环境选择、分支和合并、构建命令、AppID 核验、产物路径及项目特有验收规则，并输出实际项目、环境、构建分支和 SHA、目标 AppID、产物目录。此目录内的子技能是主技能显式读取的项目配置，不假定会被系统自动发现或独立调用。

## 流程

1. 区分仅打包与上传：打包不等于上传；用户要求上传或发布才执行上传。按项目子技能确认并构建，保护已有改动，核实项目、目标 AppID 与完整产物，并记录实际构建提交 SHA。分支和环境选择以项目子技能及用户的明确要求为准。
2. 上传前核对用户目标、上传版本、备注和实际产物。版本默认为 `1.0.0`，用户指定时以用户指定为准；备注默认填写环境名称。缺少项目配置时，仅在本次产物目录补建有效的 `project.config.json`，至少核对 `appid`、`compileType: "miniprogram"` 和 `miniprogramRoot: "./"`，并按工具要求补齐项目名称；不要覆盖用户的现有配置。
3. 默认通过本机微信开发者工具上传，读取 [开发者工具准备与上传](references/devtools.md)。只有用户明确指定使用上传密钥与 IP 白名单方式，且密钥及白名单可用时，才采用 [miniprogram-ci 准备与上传](references/miniprogram-ci.md)。用户明确指定该方式但条件不足时，说明缺少什么并等待处理，不擅自换方式上传。用户仅提供了密钥或白名单并不等于指定该方式。
4. 准备中能自动完成的检测、安装及配置检查主动完成；二维码登录、平台管理员权限、弹窗授权、后台白名单和私钥获取等必须由有权限的用户操作的事项，说明具体位置及所需操作，等待结果。不要要求用户发送私钥内容、登录凭据或 token；按引用文档安全使用。
5. 如工具返回异步任务，轮询至明确成功或失败；待处理、取消、超时不能报告为成功。上传成功仅表示代码上传成功，不等于已设为体验版、提交审核或上线；除非用户另有要求，不执行这些额外操作。在最终汇报前，按项目子技能执行打包收尾，再按下方固定格式报告。

微信开发者工具 CLI 最终返回 `√ upload` 即判定本次代码上传成功，无需再查微信公众平台。只有命令名或进度中的 `Upload`、或仅有退出码 0，不算成功。其他上传渠道以对应工具的明确成功结果为准。是否已设为体验版由用户自行确认，不是上传成功的验收条件。

## 打包结果格式

每次打包完成后先说明实际结果，再按下方顺序输出六项。用本次核实的值替换占位符，不沿用历史值或固定某个环境、应用名称。

- 微信开发者工具上传成功：「<环境> <端别>小程序「<小程序名称>」已打包并上传成功，微信开发者工具返回 `√ upload`。是否已设为体验版，请在微信公众平台确认。」其他渠道只写实际工具及其成功结果。
- 仅打包：「<环境> <端别>小程序「<小程序名称>」已打包，未上传。」
- 打包成功但未确认上传成功：说明上传失败、取消或待确认及实际原因，不写为已上传。

- **打包分支**：`<实际分支>`，提交ID: `<短 SHA>`，提交内容「<Git 提交标题>」
- **后端接口地址**：[<实际地址>](<实际地址>)
- **AppID**：`<实际 AppID>`
- **上传版本**：`<实际上传版本>`，备注「<实际上传备注>」
- **构建耗时**：约 <分> 分 <秒> 秒，不含上传
- **产物目录**：`<绝对路径>`

提交 ID 和标题取实际构建提交，可用 `git show -s --format="%h %s" <构建 SHA>`；后端接口地址填写小程序本次打包实际连接的接口根地址，以产物核验结果为准。构建耗时取本次编译与加固日志或实际计时，不含拉取代码、获取配置和上传。仅打包时保留“上传版本”项并填“未上传（仅打包）”；上传失败或待确认时如实标明状态，不写成已上传。必要时在列表后补充上传方式、主工作树同步结果或验证限制。
