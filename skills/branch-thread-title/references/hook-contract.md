# Codex 分支会话标题钩子契约

## 触发与输入

在 `UserPromptSubmit` 接收会话 ID、用户提示词和工作目录。无效输入或无关事件直接空操作，不阻塞请求。

## 标题规则

- 严格格式：`固定前缀 | 最新任务摘要`。
- 固定前缀优先使用首次任务时的 Git 分支；首次没有分支则使用首次任务摘要。首次分支即使为空也应持久化，后续分支变化不能改变前缀。
- 每次用户提示时提供当前标题与判断上下文。首次未有符合规则的标题时调用工具；已有标题时，仅当用户明确切换到明显不同的任务且摘要需要改变时调用。闲聊、问候、感谢、补充、纠正、确认、进度询问、相关追问以及不确定的情况均保留当前标题。生成的完整标题与当前标题相同时不调用工具。
- 无分支且尚未有首次摘要时，让模型从首次用户请求提炼；首次标题两侧可以一致。后续优先从首次成功的标题工具结果取固定前缀。
- 确需更新时模型调用 `set_thread_title` 并传入真实完整标题；用户明确要求保留或指定标题时应遵从。

## 状态和兼容性

按会话 ID 原子保存首次分支、首次请求及手动标题状态。保留历史状态中的首次分支，即使其值为空。可以通过会话记录中成功返回当前会话 ID 和标题的工具调用判断已生成的标题；不要仅依赖可能滞后的线程数据库标题。

利用桌面会话标题索引及已确认的工具结果尽力检测手动改名；检测到后停止自动更新。索引或历史缺失时无法保证检测所有手动改名。旧状态的 `done` 只表示旧规则的一次命名已完成，不能阻止新规则在后续任务中更新。

Windows 的标准输入按 UTF-8 解析，输出使用 ASCII 转义 JSON，避免控制台代码页损坏中文。状态、索引、历史或 Git 不可用时尽力处理并失败放行。

## 验证场景

- 有分支：`首次分支 | 首次任务`，之后变为 `首次分支 | 最新任务`。
- 无分支：`首次任务 | 首次任务`，之后变为 `首次任务 | 最新任务`。
- 切换分支后固定前缀不变，首次无分支也不能补入后续分支。
- 原任务的补充、纠正和追问不调用标题工具；明显切换任务才更新，候选标题相同时不调用；手动指定或保留标题时尊重用户意图。
- 已有旧版状态可以继续按新规则更新；工具调用失败或属于其他会话时不能当作成功。
- 无效输入或数据读取失败不阻塞用户任务。
